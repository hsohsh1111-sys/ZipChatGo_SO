# 집찾GO 프로세스 정의서

## 1. 기본 매물 탐색

1. 사용자가 지도 페이지에 진입한다.
2. 지도와 현재 매물 목록을 확인한다.
3. 지역·단지명·주소 또는 조건을 입력한다.
4. Frontend가 Spring Boot 지도 API를 호출한다.
5. 결과 목록과 마커를 갱신한다.
6. 사용자는 매물을 선택해 상세 정보를 확인하고 관심매물 동작으로 이동할 수 있다.

**예외:** 검색 결과가 없으면 빈 결과 상태를 표시한다. 요청 실패 시 재시도 가능한 오류 안내를 제공해야 한다.

## 2. AI 대화 및 지도 Action

1. 사용자가 지도 화면 AI 채팅창에 질문한다.
2. Frontend가 현재 페이지·지도·선택 매물·필터 등 허용된 App State와 최근 대화 문맥을 구성한다.
3. Frontend가 Spring Boot `POST /api/ai/chat`으로 요청한다.
4. Spring Boot가 요청을 FastAPI `POST /agent/chat`으로 전달한다.
5. FastAPI가 모델에 질문과 구조화된 상태를 전달한다.
6. 모델이 답변하거나 매물·역·POI·법률 검색 도구 호출을 선택한다.
7. 검색 도구는 필요한 Spring API 또는 법률 검색기에 질의한다.
8. 도구 결과를 바탕으로 자연어 답변과 제한된 Action을 만든다.
9. Frontend가 응답 Action을 허용 목록과 스키마 기준으로 검사해 실행한다.
10. 대화 답변을 표시하고 필요한 경우 지도·매물 UI를 갱신한다.

**예외 처리:** OpenAI 오류, Spring 내부 API 오류, 잘못된 Action 인자, 법률 검색기 미설정은 오류 응답으로 구분한다. API Key나 내부 Secret은 사용자 응답·로그·문서에 포함하지 않는다.

## 3. 관심매물 처리

1. 사용자가 매물 상세나 AI 응답에서 관심매물 동작을 선택한다.
2. Frontend 또는 Spring API가 사용자 인증 상태와 매물 ID를 확인한다.
3. 저장/삭제/조회 결과를 화면에 반영한다.

AI가 반환할 수 있는 `ADD_FAVORITE`·`REMOVE_FAVORITE` Action은 확인되지만, 관심매물 저장소의 영속성과 계정별 동작은 배포 설정 및 해당 API 구현 기준으로 확인해야 한다.

## 4. 부동산법 질의

1. FastAPI Agent가 질문을 법률 검색이 필요한 요청으로 판단한다.
2. 법률 검색 도구가 설정된 Vector Store retriever에 질의한다.
3. 검색 근거를 답변 생성 단계에 전달한다.
4. AI가 참고 근거와 불확실성을 고려해 설명한다.

검색기가 설정되지 않았거나 자료를 찾지 못하면 최신 법률을 확인한 확정 답변처럼 응답하지 않아야 한다. 운영에서 사용하는 법률 문서의 기준일과 출처를 별도로 관리해야 한다.

## 5. 운영자·등록자 매물 관리

1. 등록자가 매물 등록 화면에서 필수 정보를 입력한다.
2. Frontend가 입력값을 검증하고 Spring API로 제출한다.
3. Spring Boot가 인증·권한 및 도메인 검증을 수행한다.
4. 등록 결과를 내 매물 화면에서 확인한다.
5. 운영자는 관리 화면에서 등록 매물을 검토한다.

화면/API는 저장소에 존재하지만, 업로드 저장소 연결과 검수 정책은 배포 환경 기준으로 점검이 필요합니다.
